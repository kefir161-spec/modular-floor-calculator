# Текстуры раскладки

Как фото товара с plastfactor.com превращается в покрытие пола на схеме.

## Пайплайн

| Шаг | Скрипт | Артефакт |
|---|---|---|
| 1. Выбор фронтального фото для каждого SKU | `npm run build:layout-textures` | `public/data/layout-textures.json` |
| 2. Поиск области фото, пригодной для укладки | `npm run build:tile-crops` | `public/data/layout-crops.json` |
| 3. Проверка областей по всем цветам и сериям | `npm run audit:tile-crops` | `.texture-cache/tile-crop-audit.json` |

Оба JSON лежат в `public/data` и загружаются в браузере один раз. Кэш фотографий
(`.texture-cache`) не коммитится: повторный запуск скриптов не тратит сеть.

## Почему область считается офлайн

Фото каталога — модуль на однотонном фоне. Если в область попадёт фон, на схеме
между модулями появятся светлые щели. Раньше область искалась в браузере
по порогу яркости, и на светлых плитках (белый Sensor Avers, белый Factor)
плитка сама попадала под порог фона — область расширялась на весь кадр вместе
с белыми полями. Теперь область считается один раз офлайн и проверяется
по всем 741 варианту каталога, а браузер только пересчитывает её под
разрешение загруженного фото и пропорции модуля.

## Алгоритм (`src/shared/lib/tile-crop.ts`)

1. **Цвет фона** — медиана рамки кадра.
2. **Маска силуэта** — пиксель принадлежит модулю, если отличается от фона
   по цвету или несёт текстуру (белая плитка на белом фоне отличается только
   рельефом). Пороги адаптируются к шуму рамки.
3. **Заполнение разрывов** — отверстия решётчатых модулей (Aqua, Optima Duos,
   City) и засветки на глянце заполняются по самой длинной цепочке силуэта
   в строке и в столбце.
4. **Рост от центра** — прямоугольник расширяется, пока на его границе нет
   фона, затем сжимается на страховочный отступ. Так область оказывается
   строго внутри модуля: без фона, зубцов и выемок пазла.

Область хранится в долях кадра, поэтому не зависит от разрешения фото
(прокси wsrv в продакшене отдаёт другой размер).

## Особые случаи

| Серия | Особенность | Решение |
|---|---|---|
| City | на фото собраны 2×2 модуля 300×300 мм | `src/shared/config/catalog-photo-grid.ts`: берётся одна ячейка |
| Sensor Sota | модуль шестиугольный, раскладка прямоугольная | в шестиугольник вписывается квадрат — рисунок на схеме крупнее натурального |
| Canal белый (5463) | глянец засвечен в белый по центру кадра | берётся однородный участок — визуально это ровный белый |
| БронеПласт | [1] в галерее — общий ракурсный крупный план | picker берёт цветоспецифичное [0] (фронталь, как в превью каталога) |

## Критерии аудита

- `bleed` — доля фона внутри области. Должна быть 0: это источник светлых щелей.
- `cropRatio` — доля кадра. Меньше 15 % помечается как `small-crop`: рисунок
  на схеме заметно крупнее натурального (ожидаемо для City, Sota и случаев
  из таблицы выше). Аудит падает только на `bleed`, `missing-crop` и ошибках.

Контактный лист для глазами: `npm run audit:tile-crops -- --preview`
→ `.texture-cache/tile-crop-preview.png` (каждая плитка выложена сеткой 3×3).

## Обновление после смены фото на сайте

```bash
npm run build:layout-textures   # новые URL фронтальных фото
npm run build:tile-crops        # области для новых фото
npm run audit:tile-crops        # проверка всех цветов и серий
```
